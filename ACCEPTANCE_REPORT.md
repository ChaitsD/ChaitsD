# MAYGREY acceptance test — 20 October 2026

**Result: accepted for the current mock-commerce environment. Not approved for real commerce or deployment.** The established storefront identity and Phase 1 routes are preserved. No live payments, campaign video generation, external integrations or deployment were performed.

## Test execution

- Node 24, SQLite, production Vite build, and headless Chromium against a real local Express server and temporary database.
- `npm test`: **28 passing test results**, zero failures/skips (26 leaf test groups and two parent groups).
- `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`: **24 passing browser checkpoints**, no browser runtime errors or unexpected server errors in those flows.
- The running Vite/API app on port 5173 also passed a mobile product → cart coupon → checkout-quote smoke check without placing an order.
- `npm run build`: passes. React Router's bundled `use client` directive warnings are non-fatal.
- Full `npm audit`: zero known vulnerabilities at the time of this run; this is dependency evidence, not a penetration-test certification.
- Automated tests use temporary databases, private test users, generated credentials and separate uploads. They remove their fixtures afterward. No test accounts/orders are added to the development database.
- Browser traffic is divided into independent acceptance cohorts; fixture-local API counters are reset between bursts so rapid link crawling does not invalidate functional checks. Separate security tests exercise the unchanged production rate thresholds and require real 429 responses.

Reproduce from the checkout:

```sh
npm test
npm run build
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
npm audit --cache /tmp/maygrey-npm
```

Use `npx playwright install chromium` if there is no installed Chromium and omit `CHROMIUM_PATH` when using Playwright's browser.

## Issues found and fixed

| Issue                                                                                                      | Correction and regression coverage                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Other open tabs could retain old prices for 30 seconds                                                     | Added bounded, same-origin catalog invalidation streams. Storefront, stock and quotes refresh after successful mutations; checkout still revalidates totals. Tested without reload.                                        |
| Coupon application existed only in checkout                                                                | Added cart coupon controls and shared, persisted coupon state. Both views use server quotes; expiry and zero-total behavior tested.                                                                                        |
| Login trimmed passwords but signup hashed their original spaces                                            | Login now verifies the exact supplied password. A password with leading/trailing spaces round-trips successfully.                                                                                                          |
| Re-login left the browser's prior session valid; other tabs could show stale auth state                    | Revoke the previous session on successful login and synchronize auth changes across tabs. Backend access checks remain authoritative.                                                                                      |
| Customer wishes reused anonymous browser storage and could reappear or cross accounts after session expiry | Consume guest wishes at merge, make signed-in wishes server-authoritative, serialize writes and guard late responses by account owner. Refresh/removal/expired-session/cross-tab regressions pass.                         |
| Upload signatures alone accepted truncated images                                                          | Fully decode/re-encode PNG/JPEG/WebP with Sharp, enforce a 25-megapixel image ceiling and strip metadata. Corrupt, spoofed and oversized image uploads are rejected; random names and protected file permissions retained. |
| Malformed bags/body types could produce generic server errors                                              | Validate JSON objects, bag item shapes, quantities and multipart endpoints before use. Normal invalid requests return controlled 4xx responses.                                                                            |
| Rate-limit responses were plain text                                                                       | Return explicit JSON 429 errors and Retry-After headers. Verified login and API thresholds; forged forwarded IP headers cannot bypass default limits.                                                                      |
| Missing uploads/private paths fell through to SPA HTML                                                     | Missing uploaded media and dotfile/private paths return 404, with no environment/database disclosure.                                                                                                                      |
| Select controls lacked a precise label association                                                         | Added explicit control IDs and label references without visual changes. Admin selects are addressable by their exact field name.                                                                                           |
| Test status was not a permanent database attribute                                                         | Additive schema migration 2 marks every order `payment_mode=mock`. New IDs start `TEST-MG-`; admin/customer history has explicit test labels. Database guards reject real `paid` statuses under this mock-only schema.     |

## Remaining limitations and production blockers

1. **Real payments intentionally disabled.** A future live-payment schema/adapter, capture/webhook verification, reconciliation and real refund lifecycle must be implemented and tested. Merely adding keys cannot activate live commerce.
2. **Email delivery not connected.** Forgot-password queues messages only. Reset-token expiry, single use and session revocation are tested; actual delivery and verified sender configuration are pending.
3. **Courier integration absent.** Admin tracking fields work; no labels, shipments or live tracking sync are created. External tracking destination availability is unverified.
4. **Production hosting remains unverified.** Require actual HTTPS, correct trusted-proxy configuration, durable SQLite/uploads storage, backup restoration drill, monitoring and retention policies. SSE streaming must not be buffered by the deployment proxy. No deployment was performed.
5. **Single-instance architecture.** SQLite, in-memory limits and in-process invalidations must not be treated as a horizontally scaled deployment. Multiple instances need shared database/storage, rate-limit state and invalidation transport.
6. **Final media and business content are provisional.** Confirm artwork, garment specifications, size guide, shipping/return policies and business/tax copy before real orders. No campaign video was generated. Real MP4/WebM playback and full codec/container validation were not acceptance-tested because final video assets were not supplied; current video upload checks are signature-based. Review video scanning/transcoding and unreferenced asset cleanup before public use.
7. **Device-local guest data.** Guest cart/coupon and guest order access live on the ordering browser. Signed-in wishlists/orders are server-backed. Guest order recovery across devices and server-synced carts are not implemented.
8. **Browser/device coverage.** Chromium desktop and responsive viewport testing passed; physical iOS/Android, Safari/Firefox, assistive technology, load testing and independent penetration testing were not performed. Admin MFA remains a recommended pre-launch hardening task, not an implemented control.
9. **Owner admin setup remains intentional.** Provision your own credentials with `npm run admin:create`; tests do not leave a usable admin account or demo password in the development database.

No unresolved failures remain in the executed acceptance checks. These results authorize progressing with Phase 3 development, not collecting real payments or launching the store.
